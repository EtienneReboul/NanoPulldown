# Pair specs — `configs/pairs.parquet` + `configs/curated_domains.yaml`

Every pair a run folds (its config's `pairs_file:`, else `pairs:` list) is one
row of `configs/pairs.parquet`, generated by `scripts/expand_pairs.py` from the
run config's `inputs:` (see `scripts/resolve_inputs.py`), or from
`configs/baits.txt` x `configs/preys.txt` without one (AlphaPulldown's
bait-file x prey-file combinatorial convention). Re-running it only ADDS new pairs; it
never rewrites existing rows. The table is reproducible, so it is gitignored.
Every column is documented in the file's own schema metadata (Data Wrangler,
`pyarrow.parquet.read_schema`, or `scripts/parquet_utils.read_schema_metadata`).

| column                          | type                                       | meaning                                                       |
| ------------------------------- | ------------------------------------------ | ------------------------------------------------------------- |
| `pair`                          | `string`                                   | `<bait>__<prey>`, the `pairs:` entry                          |
| `bait_uniprot` / `prey_uniprot` | `string`                                   | UniProt accession                                             |
| `bait_copies` / `prey_copies`   | `int32`                                    | number of chains (AlphaPulldown `ID:N`)                       |
| `bait_regions` / `prey_regions` | `list<list<int32>>`, nullable              | `[[start, stop], ...]`, 1-based inclusive; null = full length |
| `chains`                        | `list<struct<id, name, role, sequence>>`   | ESMFold2 input order; ids A, B, C... bait copies then prey    |
| `bait_chains` / `prey_chains`   | `list<string>`                             | chain ids of each side                                        |
| `n_tokens`                      | `int32`                                    | total residues ESMFold2 folds (vs `esmfold2.max_tokens`)      |

Protein-protein only: no RNA/DNA/ligand chains.

Scripts never read the table directly: `scripts/lib_pipeline.load_pair(pair)`
returns the spec as a dict (`name`, `bait`/`prey` `{uniprot, copies, regions}`,
`sequences` = the chains, `bait_chains`, `prey_chains`, `annotation_reviewed`,
`domains`), with the curated domains below merged in.

## Curated domains — `configs/curated_domains.yaml` (hand-edited, tracked)

Only pairs you have curated appear here. Preprocessing writes a proposal to
`data/annotation/<pair>/annotation.yaml`. Copy its `domains:` block under the
pair's name and set `annotation_reviewed: true`; report figures then use it
instead of the proposal. Curation is informational only and never gates
folding. Editing an entry reruns just that pair's figures: rules carry a digest
of each pair's spec and curation as `params`.

```yaml
example_toy__example_toy:
  annotation_reviewed: true
  # Per chain id, an ordered list of segments. `kind` is one of:
  # domain | linker | disordered | morf. 1-based, inclusive. "linker" is
  # always a human call -- neither AIUPred track outputs it directly.
  domains:
    A:
      - {name: ubiquitin_fold, start: 1,  end: 72, kind: domain}
      - {name: LRGG_tail,      start: 73, end: 76, kind: disordered}
    B:
      - {name: ubiquitin_fold, start: 1,  end: 72, kind: domain}
      - {name: LRGG_tail,      start: 73, end: 76, kind: disordered}
```

`example_toy__example_toy` (a ubiquitin homodimer smoke test) is kept as the
worked reference for a curated entry.

## Display names — `configs/proteins.parquet` + `configs/protein_names.yaml`

Pairs, paths and tables stay keyed by UniProt accession. The reports label
proteins with names instead, from `configs/proteins.parquet`: one row per
accession, written by `scripts/expand_pairs.py`. Use
`python scripts/fetch_uniprot.py --backfill` for pairs expanded before the table
existed. Each row holds UniProt metadata (protein name, gene, synonyms, ordered
locus, organism, length, Swiss-Prot flag, function, subcellular location,
release) plus two resolved names:

| name         | used for                         | first available of                                                                                     |
| ------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `short_name` | axes, titles, pair labels        | gene name, input-source name (`name_column`), gene-like protein name, AGI locus (`AT3G43700`), accession |
| `long_name`  | subtitles, table column, tooltips | protein name (recommended, else submitted); placeholders such as "Uncharacterized protein" count as missing |

When several accessions resolve to the same short name, ` (<accession>)` is
appended. The exception is when exactly one of them is Swiss-Prot: that entry
keeps the plain name. UniProt metadata is cached per accession in
`data/uniprot_meta/`; delete that directory to refresh names after a UniProt
release.

`configs/protein_names.yaml` is tracked and hand-edited. It overrides either
name per accession, for a name the field uses that UniProt does not:

```yaml
Q9LMA8: {short: JAZ1}     # UniProt primary gene name: TIFY10A
```

## Run inputs — `configs/inputs_<run>.parquet`

There is one row per (accession, role) for the run named by `run_name`
(default `main`). `sources` lists the config `inputs:` sources that selected
the protein. Each `keep_columns` entry of an `ipms:` source adds a
`<source>_<column>` column (e.g. `pxd013906_logfc`). The results table joins
these values in for the prey.
